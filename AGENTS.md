# TeachAssist - помощник преподавателя

## Базовый контекст
Проект TeachAssist - помощник преподавателя университета в расписании занятий, контроле над посещением студентов, выполнением ими заданий, проставлении аттестации, надбавок за активность и дополнительные заданий.
Приоритеты: надежность > проверяемость > читаемость > производительность

## Базовая структура каталога
```
  frontend/          # UI приложения
  backend/           # серверная часть, API
  docs/              # документация по проекту
  scripts/           # скрипты
```

## Стек технологий
- **Frontend**: VueJS, Vuetify, Vite, язык JavaScript
- **Backend**: ASP.NET Core, Entity Framework Core, язык C#
- **Database**: PostgreSQL
- **Auth**: JWT

## Backend
- **Размещение**:вся серверная часть размещается в `backend/`
- **Миграции БД**: папка `backend/migrations/` 
- **Контроллеры API**: папка `backend/api/` 
- **Тесты**: папка `backend/api.tests/` 
- **Интерфейс API**: REST-JSON
- **Обработка ошибок**: Обрабатывать все исключения

## Frontend
- **Размещение**: вся UI часть размещается в `frontend/`
- **Формы ввода**: валидация всего пользовательского ввода

## Ограничения
- никогда не читай файлы *.prompt
- перед изменением логики читай `docs/`
- никогда не делай git commmit без явного указания
- Не меняй `backend/migrations/` без разрешения
- Не меняй публичные API без явной необходимости
- Не принимай архитектурные и доменные решения самостоятельно, уточняй если информации не хватает

## Рабочий процесс
1. Определяй область задачи, не читай файлы, не относящиеся к задаче
2. Сначала реализуй backend, затем frontend
3. После любых изменений запускай релевантные тесты, исправляй возникшие ошибки
4. Все изменения должны быть отражены в документации `docs/`
5. После изменений в UI запускай lint, исправляй возникшие ошибки

## Формат ответа
- Кратко резюмируй выполненные действия
- Кратко перечисли изменённые файлы, что и почему изменено
- Отдельно укажи, изменилась ли структура проекта
