# Контракт skill: Bugfix & Verify (Fix + Verify)

> Версия: 0.2-fixed | Дата: 2026-05-05 | Источник: W2 из `wf/s11-reuse/reusable-workflows.md`

---

## Название skill
**Bugfix & Verify** (кратко: `bugfix-n-verify`)

## Назначение
Автоматизировать цикл «найти баг → исправить → проверить → подтвердить приёмку» для проекта TeachAssist. Skill гарантирует, что после любого исправления:
- собираются backend и frontend
- проходят все релевантные тесты
- не нарушаются ограничения AGENTS.md
- изменения задокументированы

## Когда применять

Симптомы (конкретные, проверяемые):
- Исключение в логах или при выполнении запроса (stack trace)
- N+1 запросы к БД (обнаружены через лог EF Core или profiler)
- Warning при `dotnet build` (CS, xUnit, другие компиляторные)
- Failing test в `tests/`
- UI-ошибка с конкретным поведением: форма не валидируется, компонент Vuetify не рендерится, данные не отображаются в таблице

Границы:
- Затрагивает не более 3 файлов
- Требуется не более 2 итераций исправления
- Не меняет бизнес-логику, только устраняет отклонение от ожидаемого поведения

## Когда НЕ применять

- Новая функциональность или endpoint (→ W3)
- Рефакторинг без изменения поведения (→ W4)
- Изменение бизнес-правила или доменной модели (→ W1)
- Изменение публичного контракта API (новые поля DTO, новые HTTP-статусы, удаление полей) — требует явного разрешения пользователя
- Миграции БД — строго запрещено без явного разрешения
- Визуальная полировка без ошибки: выравнивание, цвета, отступы, шрифты (→ W7)
- Практический учебный шаг (→ W5)

## Входы (обязательные)

1. **Описание проблемы** — текст ошибки, stack trace, лог, failing test, или конкретное описание UI-поведения
2. **Контекст** — при каких условиях проявляется (какой endpoint, какая страница, какие данные)
3. **Затронутые файлы** — если известны; если нет, skill локализует самостоятельно

## Входы (опциональные)

4. **Тесты, покрывающие проблемную область** — если существуют
5. **Скриншот или запись экрана** — для UI-ошибок

## Ожидаемый результат

- Исправленный код в `backend/` и/или `frontend/` (не более 3 файлов)
- Прошедшие проверки:
  - `dotnet build` — без ошибок
  - `dotnet test` — все тесты зелёные
  - `npm run lint` — без ошибок (если затронут frontend)
- API-совместимость подтверждена через `git diff` файлов контроллеров и DTO: нет новых полей, нет изменений HTTP-статусов
- Документация в `docs/` обновлена, если изменился формат ответа endpoint-а или добавлено/удалено поле
- Готовность к commit (ожидание явного подтверждения пользователя)

## Основные шаги

| # | Шаг | Действие | Проверка / Артефакт |
|---|-----|----------|---------------------|
| 0 | **Pre-flight** | Проверка стоп-сигналов до начала работы: проблема требует изменения миграций? контракта API? > 3 файлов? | Если да — STOP |
| 1 | **Локализация** | Поиск затронутых файлов (grep, glob, read) | Список файлов (макс. 3) |
| 2 | **Покрытие тестами** | Проверка: есть ли тесты для проблемной области | Если нет — предупредить пользователя, предложить добавить тест (→ W6) |
| 3 | **Анализ причины** | Чтение кода, логов, тестов. Формулировка root cause (1-2 предложения) | Описание причины, подтверждённое пользователем |
| 4 | **Исправление** | Внесение изменений в код (backend и/или frontend) | Diff изменений |
| 5 | **Build** | `dotnet build` | Успешная сборка без ошибок |
| 6 | **Test** | `dotnet test` | Все тесты прошли |
| 7 | **Lint** | `npm run lint` (если frontend) | Линтер без ошибок; если команда не работает — предупредить пользователя |
| 8 | **Стоп-сигналы** | Проверка: нет изменений в migrations/, нет изменений DTO/контроллеров/HTTP-статусов | Если есть — STOP, запросить разрешение |
| 9 | **Документация** | Обновление `docs/` только если изменился формат ответа endpoint-а или добавлено/удалено поле | Изменения в docs |
| 10 | **Подтверждение** | Ожидание явного разрешения на commit от пользователя | — |

## Стоп-сигналы (немедленная остановка)

Применяются все ограничения AGENTS.md. Ниже — специфичные для данного skill:

| Сигнал | Условие | Действие |
|--------|---------|----------|
| Миграции БД | Исправление требует изменения `backend/migrations/` | STOP, запросить явное разрешение |
| Контракт API | Изменение DTO, сигнатуры контроллера, HTTP-статуса | STOP до исправления, запросить разрешение |
| Объём | Затронуто > 3 файлов | STOP, предложить W1 (long-horizon) |
| Итерации | > 2 итераций исправлений без успеха | STOP, предложить W1 |
| Тесты сломаны | `dotnet test` падает, причина понятна, но исправление требует изменения структуры тестов | STOP, предложить W6 |
| Тесты сломаны | `dotnet test` падает, причина не ясна | STOP, задокументировать проблему |
| Нет покрытия тестами | Проблемная область не покрыта тестами | Предупредить пользователя, предложить W6 |
| Линтер не работает | `npm run lint` не запускается или не настроен для frontend-исправлений | Предупредить пользователя, продолжить с подтверждением |
| Несоответствие стеку | Исправление требует библиотеки, не заявленной в проекте | STOP, запросить разрешение |

## Критерии приёмки (checklist)

**Обязательные:**
- [ ] `dotnet build` проходит без ошибок
- [ ] `dotnet test` проходит успешно
- [ ] `npm run lint` проходит без ошибок (если затронут frontend)
- [ ] `git diff` по файлам контроллеров/DTO не показывает новых полей, изменений HTTP-статусов или удалённых полей
- [ ] Нет изменений в `backend/migrations/`
- [ ] Получено явное подтверждение пользователя на commit

**Условные:**
- [ ] `docs/` обновлён — только если изменился формат ответа endpoint-а или добавлено/удалено поле DTO
- [ ] Regression-тест добавлен — только если проблемная область не была покрыта тестами
