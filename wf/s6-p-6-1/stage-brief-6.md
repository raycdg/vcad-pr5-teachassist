# Stage Brief: Этап 6 — Frontend ролевое отображение и защита UI

## Цель
Адаптировать frontend под ролевую модель: скрыть/показать элементы UI в зависимости от роли пользователя, защитить роуты и обеспечить корректную навигацию. UI должен полностью соответствовать правам доступа.

## Точки встраивания
- `frontend/src/App.vue` — обновление навигации и меню пользователя в зависимости от роли
- `frontend/src/router/index.js` — добавление роут-гардов с проверкой ролей
- `frontend/src/views/` — обновление страниц:
  - `Disciplines.vue` — фильтрация для преподавателя, скрытие кнопок создания
  - `Tasks.vue` — ограничение редактирования задач своих дисциплин
  - `Courses.vue` — отображение только своих курсов для преподавателя
  - `CourseProgress.vue` — ограничение редактирования оценок своих курсов
  - `Groups.vue`, `GroupDetail.vue` — скрытие для преподавателя (Manager+)
  - `Students.vue` — скрытие для преподавателя (Manager+)
- Создание директивы/компонента `v-role` для условного отображения
- Создание страницы «Доступ запрещён» (403)

## Инварианты
- **Backend**: не изменять логику API и контроллеров (этапы 1-5 уже реализовали защиту на бэкенде)
- **База данных**: не менять схему БД
- **Auth flow**: не менять логику входа, JWT и хранения токена
- **Структура проекта**: сохранять текущую архитектуру VueJS/Vuetify

## Критерии готовности
1. **Ролевое отображение**: преподаватель видит только свои дисциплины, задачи, курсы и оценки
2. **Навигация**: преподаватель НЕ видит ссылки на управление группами и студентами
3. **Навигация**: менеджер видит все ресурсы и ссылки кроме админских
4. **Навигация**: администратор видит всё плюс ссылку на управление пользователями
5. **Защита роутов**: прямой переход на запрещённый роут показывает 403
6. **Качество кода**: ESLint проходит без ошибок (`npm run lint`)
7. **Интеграция**: директива `v-role` корректно работает на всех страницах

## Зависимости
- Требует завершения этапов 1-5 (готовый backend с авторизацией и назначением преподавателей)
