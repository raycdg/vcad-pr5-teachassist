# Stage Brief: Этап 3 — Система ролей и политики авторизации

## Цель
Реализовать ролевую модель (Teacher, Manager, Admin) и политики авторизации на backend, добавить claims в JWT, создать frontend-стор авторизации и отобразить роль пользователя в UI. Защитить все существующие API endpoints политиками авторизации.

## Точки встраивания
- **Backend `Program.cs`**: регистрация политик `RequireTeacher`, `RequireManager`, `RequireAdmin` через `AuthorizationOptions.AddPolicy`
- **Backend `AuthController`**: добавление claims `role`, `userId`, `email` при генерации JWT
- **Backend Seed-данные**: создание ролей `Teacher`, `Manager`, `Admin` через `RoleManager<IdentityRole>` при старте
- **Backend Контроллеры**: добавление атрибутов `[Authorize(Policy = "RequireTeacher")]` и др. ко всем существующим endpoints
- **Frontend `stores/auth.js`**: новый Pinia-стор для хранения `role`, `email`, `userId`, `token`
- **Frontend `App.vue`**: отображение роли и email пользователя в шапке приложения
- **Frontend `router/index.js`**: обновление роут-гардов с проверкой ролей (если требуется)

## Инварианты
- Не изменять бизнес-логику внутри методов контроллеров (только добавление атрибутов авторизации)
- Не менять схему БД и не создавать новые миграции (роли создаются через Seed)
- Не затрагивать функционал управления пользователями (этап 2)
- Не реализовывать личный кабинет (это этап 4)
- Не менять логику фильтрации ресурсов по владельцу (это этап 5)

## Критерии готовности
- Роли `Teacher`, `Manager`, `Admin` существуют в базе данных (проверить через БД или API)
- JWT при логине содержит claims: `role`, `userId`, `email` (проверить декодированием токена)
- Политики `[Authorize(Policy = "RequireTeacher")]` и др. корректно возвращают 403 при несоответствии роли
- Создан и работает Pinia-стор `auth.js` с полями `role`, `email`, `userId`
- В `App.vue` отображается роль и email текущего пользователя
- Все существующие API endpoints защищены (минимум `[Authorize]` или конкретная политика)
- Существующие тесты backend проходят (или обновлены с учётом авторизации)
- ESLint frontend проходит без ошибок
