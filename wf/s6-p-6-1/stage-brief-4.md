# Stage Brief: Этап 4 — Личный кабинет пользователя

## Цель
Создать личный кабинет пользователя с возможностью просмотра профиля, смены email (с подтверждением старым паролем) и смены пароля. Backend обеспечивает API, frontend — UI с валидацией.

## Точки встраивания
- **Backend**: создать `AccountController` в `backend/Api/Controllers/` с endpoints:
  - `GET /api/account/profile` — получить данные текущего пользователя
  - `PUT /api/account/email` — сменить email (с подтверждением через старый пароль)
  - `PUT /api/account/password` — сменить пароль (требует старый пароль)
- **Backend**: добавить защиту всех endpoints AccountController политикой `RequireTeacher` (доступно всем авторизованным)
- **Backend**: создать DTO-классы в `backend/Api/DTOs/` для запросов смены email и пароля
- **Frontend**: создать страницу `/profile` (компонент `Profile.vue`) со формами смены email и пароля
- **Frontend**: добавить ссылку на профиль в меню пользователя в `App.vue`
- **Frontend**: добавить роут `/profile` в `router/index.js` с защитой (require auth)
- **Frontend**: добавить валидацию форм (email уникальность, пароль по требованиям Identity)

## Инварианты
- Не менять существующие контроллеры и их логику (кроме добавления AccountController)
- Не менять схему БД (AppUser уже содержит нужные поля)
- Не затрагивать функционал управления пользователями администратором (этап 2)
- Не реализовывать подтверждение email через ссылку (SMTP) — только через старый пароль
- Не инвалидировать JWT при смене пароля (выходит за рамки этапа)
- Не менять логику ролей и политик (это этап 3, уже реализовано)

## Критерии готовности
- `GET /api/account/profile` возвращает данные текущего пользователя (email, возможно роль, userId)
- `PUT /api/account/email` работает: требует старый пароль, проверяет уникальность нового email, успешно меняет email
- `PUT /api/account/password` работает: требует старый пароль, проверяет требования Identity к новому паролю, успешно меняет пароль
- После смены email пользователь остаётся в системе (токен не инвалидируется, или выдаётся новый — уточнить)
- Frontend страница `/profile` отображает данные профиля, имеет формы смены email и пароля
- Формы на frontend имеют валидацию и показывают ошибки от backend
- Роут `/profile` защищён (редирект на /login для неавторизованных)
- Ссылка на профиль видна в шапке (App.vue) для всех авторизованных пользователей
- ESLint frontend проходит без ошибок
- Существующие тесты backend продолжают проходить (или добавлены тесты на AccountController)
