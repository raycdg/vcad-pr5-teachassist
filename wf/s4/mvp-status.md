## 2. Сквозной пользовательский сценарий

**Ключевой сценарий из MVP работает целиком:**

1. **Создание группы и добавление студентов**
   - Переход на `/groups` → кнопка "Add Group" → заполнение формы → сохранение
   - Переход в деталь группы → кнопка "Add Student" → добавление студентов (имя, фамилия, email)

2. **Создание учебного предмета и заполнение списком заданий**
   - Переход на `/disciplines` → кнопка "Add Discipline" → заполнение формы
   - Переход к заданиям предмета (кнопка с иконкой clipboard) → добавление заданий с выбором типа оценки

3. **Создание учебного курса**
   - Переход на `/courses` → кнопка "Add Course" → выбор предмета, группы, указание года
   - Курс создается активным по умолчанию

4. **Отметка выполнения заданий и уведомление студентов**
   - Переход в прогресс курса (кнопка с иконкой table)
   - Матрица: строки = студенты, столбцы = задания
   - Ввод оценок в редактируемые ячейки (фиксированная колонка с именами при скролле)
   - Фильтрация студентов по имени/фамилии
   - Кнопка "Save" — сохранение всех изменений
   - **Автоматическая отправка email-уведомлений студентам** (асинхронно через `GradeNotificationAdapter`)

5. **Просмотр прогресса группы**
   - Страница прогресса отображает текущие оценки из БД
   - Сортировка по фамилии и имени
   - Фильтрация

6. **Закрытие учебного курса**
   - На странице `/courses` кнопка с иконкой X (для активных) или ✓ (для неактивных)
   - Переключение статуса через `toggle-status`
   - После деактивации редактирование оценок блокируется (и на бэкенде, и на фронтенде)

**Вывод**: Сценарий можно пройти от начала до конца, все шаги реализованы и протестированы.

## 5. Дальнейшие улучшения (планирование)

### 5.1 Авторизация и безопасность (приоритет №1)
**Зачем**: Сейчас API полностью открыт, любой может создавать/удалять данные  
**Что сделать**:
- Добавить JWT-авторизацию для преподавателя (уже указано в стеке технологий)
- Защитить endpoints с помощью `[Authorize]`
- Добавить личный кабинет преподавателя с возможностью смены пароля
- (Опционально) Личные кабинеты студентов для просмотра своих оценок

### 5.2 Улучшение системы уведомлений (приоритет №2)
**Зачем**: Текущая реализация отправляет email напрямую при сохранении, что может замедлить ответ API  
**Что сделать**:
- Внедрить очередь сообщений (например, фоновые задачи через `IHostedService` или библиотеку Hangfire)
- Добавить шаблоны писем (например, через Razor Templates)
- Добавить логирование отправленных уведомлений в БД
- Добавить уведомления внутри приложения (in-app notifications) для преподавателя

### 5.3 Расписание занятий и посещаемость (приоритет №3)
**Зачем**: Следующий логический шаг после контроля заданий — учет посещаемости  
**Что сделать**:
- Модель "Занятие" (предмет, дата, время, тип: лекция/практика)
- Отметка посещаемости студентами (присутствовал/отсутствовал/уважительная причина)
- Календарь расписания на дашборде
- Напоминания о предстоящих занятиях (email или in-app)
