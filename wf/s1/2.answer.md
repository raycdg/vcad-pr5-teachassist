### 1. Точка встраивания
- **Backend**: Новый контроллер `TasksController` в `backend/api/`. Маршрутизация будет привязана к дисциплинам (например, `/api/disciplines/{disciplineId}/tasks`).
- **Frontend**: Роут вида `/disciplines/:id/tasks`. Переход инициируется из компонента списка предметов (Disciplines) через кнопку в колонке `actions`.

### 2. Минимальный набор файлов
**Backend:**
- `backend/Models/DisciplineTask.cs` (новая сущность)
- `backend/api/TasksController.cs` (новый контроллер)
- `backend/Data/ApplicationDbContext.cs` (добавление `DbSet<DisciplineTask>`)

**Frontend:**
- `frontend/src/views/TasksView.vue` (новая страница)

- Файл компонента, содержащий таблицу предметов (для добавления кнопки "Задания")

### 3. План выполнения
1. **Модель данных**: Создать класс `DisciplineTask` со свойствами: `Id`, `DisciplineId` (FK), `Number` (int, порядковый номер), `Name` (string), `GradingType` (enum: 1 - pass/fail, 2 - score), `MaxScore` (int?, nullable).
2. **БД**: Обновить `ApplicationDbContext`, добавить миграцию (по согласованию) и применить её.
3. **Backend API**: Реализовать `TasksController`:
   - `GET` (список с фильтрацией по названию и сортировкой по `Number`)
   - `POST` (создание: вычисление следующего `Number`)
   - `PUT` (обновление)
   - `DELETE`
   - `PATCH /priority` (логика swap для `Number` при повышении/понижении приоритета)
4. **Frontend Роутинг**: Прописать путь к `TasksView`.
5. **Frontend Страница**: 
   - Таблица (Vuetify) с колонками из брифа.
   - Реализовать фильтрацию (search field).
   - Диалог создания/редактирования (валидация: Name и Type обязательны, MaxScore обязателен только для `score`).
   - Кнопки "Вверх/Вниз" для смены приоритета.
6. **Интеграция**: Добавить кнопку "Задания" в строку таблицы предметов, ведущую на `/disciplines/{id}/tasks`.

### 4. Риски расползания scope
- **Связь с оценками**: Сейчас создается только "шапка" задания. Важно не начать реализовывать логику выставления оценок студентам за эти задания (это следующий шаг MVP).
- **Справочник типов**: Риск захотеть вынести `pass/fail` и `score` в БД. Бриф запрещает — оставляем хардкод.
- **Валидация на Backend**: Легко уйти в глубокую валидацию (например, проверка уникальности номеров в транзакции). Стоит ограничиться базовой логикой.
- **UI/UX предметов**: Изменение страницы предметов только ради добавления кнопки. Не менять ничего кроме `actions`.
