### Цель
Добавить ведение списка заданий (discipline tasks) для учебных предметов (disciplines)
Является шагом реализации MVP из wf/s1/mvp.md

### Контекст
В приложение добавляется страница Tasks, на странце размещена таблица заданий.

Для задания задаются:
- порядковый номер, число, автоматически проставляется для нового задания следующим свободным номером, не редактируется напрямую
- название (обязательное поле)
- тип оценивания (обязательное поле): варианты `pass/fail` (код 1), `score` (код 2)
- максимальная оценка (актуально и обязательно только для типа `score`)

Все задания выводятся в упорядоченно по порядковому номеру. Имеется быстрая фильтрация по строке на совпадение названия.

Для заданий необходимы операции CRUD плюс операции повышения приоритета (поменять порядковый номер с предыдущим заданием) и понижения приоритета (поменять порядковый номер со следующим заданием)

Переход на страницу заданий выполняется со страницы предметов от предметы в поле actions (добавить кнопку).

### Инварианты
- не меняется логика уже существующих маршрутов и страниц (групп, студентов)
- не изменяются уже существующие модели данных

### Не входит в этот проход
- пока не заводим для типов оценивания заданий отдельного справочника, типы захардкодить
- пока не делаем тесты по данной фиче

### Критерии готовности
- Проверка вручную подтверждает переход от страницы предметов к правильной странице заданий
- Проверка вручную подтверждает отображение списка заданий предметов, CRUD-операции, изменнеие приоритета, фильтрацию
- Все уже существующие тесты backend проходят без ошибок
