# Feature Brief: Итерация 2 — Учебные курсы и прогресс студентов

## 1. Цель
Обеспечить преподавателя инструментом для сопоставления учебных предметов с группами студентов (создание учебных курсов) и интерфейсом для массового ввода оценок и контроля выполнения заданий.

## 2. Описание функционала

### 2.1. Управление учебными курсами
*   **Сущность «Учебный курс»**: объединяет предмет и группу студентов для конкретного периода обучения.
*   **Поля курса**:
    *   Связь с Предметом (из Итерации 1).
    *   Связь с Группой (из исходного состояния).
    *   Год обучения.
    *   Статус «Активен» (boolean).
*   **CRUD-операции**: Возможность создания, просмотра, редактирования и удаления курсов.
*   **Управление статусом**: Возможность переключать курс в статус «Активен» или «Неактивен».
    *   *Ограничение*: В неактивных курсах блокируется редактирование оценок студентов.
*   **Список курсов**:
    *   По умолчанию отображаются только активные курсы.
    *   Переключатель «Показать все курсы» / «Скрыть неактивные» для отображения архивных данных.

### 2.2. Страница прогресса студентов (Ввод оценок)
*   **Табличный вид**: Отображение успеваемости в виде матрицы.
    *   **Строки**: Студенты выбранной группы.
    *   **Столбцы**: Задания, привязанные к предмету курса.
*   **Фиксация области**: При горизонтальном скроллинге колонка с именем и фамилией студента должна оставаться видимой (sticky).
*   **Фильтрация и сортировка**:
    *   Поиск/фильтрация студентов по имени и фамилии.
    *   Сортировка списка студентов по фамилии и имени.
*   **Ввод данных**:
    *   Ячейки таблицы редактируемы. Тип ввода зависит от типа задания (Зачёт/Незачёт или Балльная оценка).
    *   Изменения в таблице не сохраняются мгновенно.
*   **Сохранение**: Кнопка «Сохранить», которая отправляет все накопленные изменения в БД пакетом.

## 3. Критерии приемки (Acceptance Criteria)
1.  Преподаватель может создать курс, выбрав существующие предмет и группу.
2.  Преподаватель может менять статус курса на «Неактивен»; при этом интерфейс ввода оценок для этого курса становится недоступным (read-only).
3.  В списке курсов работает переключение между активными и всеми курсами.
4.  Страница прогресса корректно отображает список студентов группы и задания предмета.
5.  При вводе оценок и обновлении страницы данные не теряются (до нажатия «Сохранить» они хранятся в состоянии UI, после нажатия — в БД).
6.  Имена студентов остаются видимыми при скролле таблицы вправо.

## 4. Что не входит в итерацию (Out of Scope)
*   Отправка email-уведомлений студентам (Итерация 3).
*   Автоматический расчет итоговой аттестации (входит в «Пока не входит в MVP»).
*   Авторизация преподавателя (пока используется общий доступ).

## 5. Зависимости

*   Наличие реализованного функционала Предметов и Заданий (Итерация 1).
