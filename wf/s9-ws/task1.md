# Работа с изолированными worktrees

## Цель

Создать изолированный worktree через git и выполнить в нем потенциально опасную задачу

## Работа с worktree через git

Пусть проект находится в каталоге `project/`, bash открыт в этом каталоге

```bash
# Создать worktree в соседнем каталоге с проектом `project-feature-a/` и дать ему имя `feature-a`
git worktree add ../project-feature-a -b feature-a

# Запустить агент в нужном worktree
cd ../project-feature-a && opencode

# Посмотреть список активных worktrees
git worktree list

# Убрать worktree после завершения
git worktree remove ../project-feature-a
```

## Задача

На предыдущем спринте был сделан коде-верью для бэкенда и для тестов бэкенда. отчет по ревью лежит в файле: wf/s8-parallel/2.result.md
Можно дать задачу агенту разобрать этот ревью и выполнить рекомендации. Это сложная задача, потенциально может все поломать, поэтому запустим ее в отдельном worktree.

## Реализация

* Создадим новый worktree с названием `refactor-backend`:

```bash
git worktree add ../refactor-backend -b refactor-backend
```

* Запустим агента в нужном worktree

```bash
cd ../refactor-backend && opencode
```

* Зададим ему промпт для выполнения рефакторинга по коде ревью бэкэнда (исключая тесты). Поскольку в отчете не одно предложение рефакторинга, а много различных, после каждого замечания он должен проверить все тесты и убедиться, что они все работают, только потом коммитить и переходить к следующему. Контекст задачи не бесконечный, так что заставим его запускать каждый рефакторинг в отдельном субагенте @general. Чтобы он не зависал долго над одной задачей нужно дать ему критерии, когда нужно сдаться и бросить рефакторинг. После завершения пусть формирует отчет, какие предложения по рефакторингу он закрыл, какие не получилось. Промпт следующий:

```txt
Прочитай отчет по коде-ревью wf/s8-prallel/2.result.md
Нужно выполнить предложенные задачи по рефакторингу backend, но только не тестов. Все предложения по изменению/рефакторингу тестов проигнорируй.
Каждую задачу запускай последовательно в отдельном агенте general. Агент должен выполнить предложенный рефакторинг или изменение, проверить, что все тесты проходят и сформировать краткий отчет по выполненной работе: какая задача закрыта, сколько изменений в каких файлах. Если рефакторинг выполнить не удается, агент должен вернуть краткий отчет, почему не получилось выполнить задачу.
После завершения работы агента и получения от него отчета, сделай локальный коммит, только затем запускай следующего агента на следующую задачу (кроме задач тестового слоя) и так до конца.
В финале сделай общий отчет, по закрытым и не закрытым задачам. Отчет сохрани в файл wf/s9-ws/report.md
```

## Приемка результатов работы

После окончания работы агента проходим по отчету в рабочей ветке `refactor-backend`. Смотрим все коммиты, изменения в коммитах. Если этот коммит устраивает, то переносим его в основную ветку. Из основного каталога проекта:

```bash
git cherry-pick <hash>
```

## Зачистка ветки

Когда больше ничего полезного в ветке не осталось и остальное можно отбросить, удаляем ветку:

```bash
git worktree remove ../refactor-backend --force
```
