# Backend Code Review - TeachAssist Project

## Critical Issues

### 1. **Hardcoded Admin Credentials in Production Code**
- **Importance**: Critical
- **File**: `E:\vibe-projects\teachassist-5\backend\Program.cs` (lines 104-106)
- **Issue**: Admin email (`admin@teachassis.local`) and password (`admin`) are hardcoded directly in the source code. This is a severe security vulnerability.
- **Suggested Improvement**: 
  - Remove hardcoded credentials
  - Use configuration/secrets management (e.g., `appsettings.json`, environment variables, or Azure Key Vault)
  - Ensure default admin password is randomly generated or requires change on first login
  - Add warning if default credentials are detected in production

### 2. **Weak Password Policy**
- **Importance**: Critical
- **File**: `E:\vibe-projects\teachassist-5\backend\Program.cs` (lines 38-43)
- **Issue**: Password requirements are set to minimum (4 characters, no digit/lowercase/uppercase/non-alphanumeric required). This makes the system vulnerable to brute-force attacks.
- **Suggested Improvement**:
  - Require at least 8 characters
  - Require at least one digit, one lowercase, one uppercase
  - Consider adding password strength validation on the client side as well
  - Minimum should be: `RequiredLength = 8`, `RequireDigit = true`, `RequireLowercase = true`, `RequireUppercase = true`

### 3. **JWT Secret Key Not Properly Secured**
- **Importance**: Critical
- **File**: `E:\vibe-projects\teachassist-5\backend\Program.cs` (line 50) and `E:\vibe-projects\teachassist-5\backend\Api\Controllers\AuthController.cs` (line 55)
- **Issue**: The JWT secret key is read from configuration without validation. If the secret key is not configured or is too short, the application may crash or be insecure. No validation that the key meets minimum security standards (e.g., at least 32 characters for HMAC-SHA256).
- **Suggested Improvement**:
  - Validate secret key length during startup (minimum 32 characters)
  - Store secret key in secure configuration (not in source control)
  - Consider using asymmetric keys (RSA) for better security
  - Add startup validation that throws clear error if key is invalid

### 4. **Sensitive SMTP Credentials in Plain Text**
- **Importance**: Critical
- **File**: `E:\vibe-projects\teachassist-5\backend\Api\Options\SmtpOptions.cs` and configuration
- **Issue**: SMTP password is stored as plain string. No indication of encryption or secure storage.
- **Suggested Improvement**:
  - Use `IConfiguration` with Azure Key Vault or similar secure storage
  - Document that SMTP password should be stored securely
  - Consider supporting environment variables for credentials

### 7. **Multiple Calls to GetUserAsync in Same Context**
- **Importance**: High
- **File**: `E:\vibe-projects\teachassist-5\backend\Api\Controllers\CoursesController.cs` (lines 84-85), `TasksController.cs` (lines 35-36)
- **Issue**: Repeated calls to `_userManager.GetUserAsync(User)` within the same request context. This hits the database multiple times unnecessarily.
- **Suggested Improvement**: Cache the user in a local variable or use a helper method that caches within the request scope.

### 8. **No Transaction Management for Multi-Step Operations**
- **Importance**: High
- **File**: `E:\vibe-projects\teachassist-5\backend\Api\Controllers\CoursesController.cs` (lines 113-122)
- **Issue**: When creating a course and assigning a teacher, these are two separate `SaveChangesAsync()` calls without a transaction. If the second operation fails, the course is orphaned.
- **Suggested Improvement**: Wrap related operations in a database transaction:
  ```csharp
  using var transaction = await _context.Database.BeginTransactionAsync();
  try
  {
      // operations
      await _context.SaveChangesAsync();
      await transaction.CommitAsync();
  }
  catch
  {
      await transaction.RollbackAsync();
      throw;
  }
  ```

### 9. **Insecure File Logging Implementation**
- **Importance**: High
- **File**: `E:\vibe-projects\teachassist-5\backend\Api\Logging\FileLoggerProvider.cs` (lines 27-33)
- **Issue**: Uses `File.AppendAllText` which opens and closes the file for each log message. This is inefficient and can cause file locking issues in concurrent scenarios. Also uses `DateTime.Now` instead of `DateTime.UtcNow`.
- **Suggested Improvement**:
  - Use `StreamWriter` with proper async methods
  - Implement proper async file logging with queued writes
  - Use UTC time for consistency: `DateTime.UtcNow`

### 10. **No Pagination on List Endpoints**
- **Importance**: High
- **File**: Multiple controllers (CoursesController, DisciplinesController, etc.)
- **Issue**: All list endpoints return full collections without pagination. This can cause performance issues with large datasets.
- **Suggested Improvement**: Add pagination parameters (`page`, `pageSize`) and return paged results with metadata (total count, pages, etc.).
