# Parallel Code Review Results

## Branch A: Backend Code Review

Based on my thorough review of the backend directory, here are the issues found, ordered by descending importance:

---

### 1. **Critical Security: Hardcoded JWT Secret Key in Configuration**
- **Importance**: Critical
- **File**: `backend/appsettings.json` (line 24)
- **Issue**: The JWT secret key is hardcoded in the configuration file with a weak, predictable value: `"TeachAssistSuperSecretKeyForJwtTokenGeneration2026!"`
- **Recommendation**: 
  - Move the secret key to environment variables, Azure Key Vault, or another secure secret management system
  - Use a strong, randomly generated key (at least 256 bits)
  - Update `Program.cs` to read from `Environment.GetEnvironmentVariable("JWT_SECRET_KEY")` or use `IConfiguration` with user secrets for development

---

### 2. **Critical Security: Weak Password Policy and Hardcoded Admin Credentials**
- **Importance**: Critical
- **File**: `backend/Program.cs` (lines 37-44, 104-106)
- **Issue**: 
  - Password policy requires only 4 characters with no complexity requirements (lines 37-44)
  - Admin credentials are hardcoded: email `admin@teachassis.local`, password `admin`
  - This creates a severe security vulnerability
- **Recommendation**:
  - Enforce strong password policy (minimum 8 characters, require digit, lowercase, uppercase, non-alphanumeric)
  - Remove hardcoded admin credentials; use environment variables or a setup script
  - Consider using `dotnet user-secrets` for development and environment variables for production

---

### 3. **Critical Security: Database Credentials Exposed in Configuration**
- **Importance**: Critical
- **File**: `backend/appsettings.json` (line 19), `backend/domain/Data/DomainDbContextFactory.cs` (line 18)
- **Issue**: Database connection string with username and password is exposed in plain text in configuration files
- **Recommendation**:
  - Use environment variables: `Host=localhost;Port=5433;Database=teachassist_3_1;Username=${DB_USER};Password=${DB_PASSWORD}`
  - Or use `IConfiguration.GetConnectionString()` with Azure Key Vault / environment variable substitution
  - Add `appsettings.json` to `.gitignore` or ensure secrets are not committed

---

### 4. **High: Missing Global Exception Handling**
- **Importance**: High
- **File**: `backend/Program.cs` (entire file)
- **Issue**: No global exception handling middleware is configured. Unhandled exceptions will return default ASP.NET Core error pages with potentially sensitive information exposed
- **Recommendation**:
  - Add middleware: `app.UseExceptionHandler("/error")` or use `UseMiddleware<ExceptionHandlingMiddleware>()`
  - Create a custom exception handling middleware that returns consistent ProblemDetails responses
  - Log all unhandled exceptions

---

### 5. **High: No Rate Limiting on Authentication Endpoints**
- **Importance**: High
- **File**: `backend/Api/Controllers/AuthController.cs` (lines 25-50)
- **Issue**: The login endpoint has no rate limiting, making it vulnerable to brute-force attacks
- **Recommendation**:
  - Add rate limiting using `AspNetCoreRateLimit` NuGet package or ASP.NET Core 10's built-in rate limiting
  - Implement account lockout after failed attempts using ASP.NET Core Identity's built-in lockout feature

### 6. **High: N+1 Query Problem in Teacher Lookups**
- **Importance**: High
- **File**: `backend/Api/Controllers/CoursesController.cs` (lines 350-356), `backend/Api/Controllers/DisciplinesController.cs` (lines 189-195)
- **Issue**: Both `GetCourseTeachers` and `GetDisciplineTeachers` methods make separate database calls to `UserManager.FindByIdAsync()` for each teacher ID, causing N+1 query problems
- **Recommendation**:
  - Batch lookup teachers or join with Identity tables
  - Consider adding a method to UserManager or using `Where(u => teacherIds.Contains(u.Id))` to fetch all at once
  - Example fix for CoursesController:
    ```csharp
    var teachers = await userManager.Users
        .Where(u => teacherIds.Contains(u.Id) && !u.IsDeleted)
        .Select(u => new TeacherDto { Id = u.Id, Email = u.Email ?? string.Empty })
        .ToListAsync();
    ```

### 7. **High: Fire-and-Forget Async Call**
- **Importance**: High
- **File**: `backend/Api/Controllers/CoursesController.cs` (line 305)
- **Issue**: `_ = _notificationAdapter.NotifyGradesSavedAsync(id, dto.Grades, CancellationToken.None);` - fire-and-forget pattern that can lead to unhandled exceptions and lost notifications
- **Recommendation**:
  - Use a proper background job queue (e.g., `IHostedService`, Hangfire, or Azure Functions)
  - Or at minimum, log exceptions:
    ```csharp
    _ = Task.Run(async () => 
    {
        try { await _notificationAdapter.NotifyGradesSavedAsync(id, dto.Grades, CancellationToken.None); }
        catch (Exception ex) { _logger.LogError(ex, "Failed to send grade notifications"); }
    });
    ```

- **Importance**: Medium
- **File**: `backend/Api/Services/GradeNotificationAdapter.cs` (lines 130-152)
