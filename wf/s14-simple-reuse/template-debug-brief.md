# Debug Brief Template — TeachAssist

> **Назначение**: Шаблон для фиксации проблемы/бага перед началом исправления.
> **Версия**: 1.0 | **Дата**: 2026-05-06

---

## Когда использовать

- Обнаружен баг, требующий анализа перед исправлением
- Получен баг-репорт от пользователя или из логов
- Требуется зафиксировать контекст проблемы до начала работы (W2 из `wf/s11-reuse/reusable-workflows.md`)

---

## Шаблон

Заполни поля ниже перед началом исправления:

```markdown
### Проблема

- **Описание**: <краткое описание бага, что происходит неправильно>
- **Где обнаружен**: <backend / frontend / оба>
- **Симптомы**: <что видит пользователь или что в логах>
- **Воспроизведение**: <шаги для воспроизведения, если известны>

### Контекст

- **Затронутые файлы**: <список файлов, которые могут быть связаны>
- **Связанные endpoint-ы / компоненты**: <если применимо>
- **Предшествующие изменения**: <какой коммит/PR мог вызвать проблему>

### Гипотеза

- **Возможная причина**: <предположение о корневой причине>
- **Уровень уверенности**: <высокий / средний / низкий>

### План исправления

- **Шаг 1**: <что сделать первым>
- **Шаг 2**: <что сделать вторым>
- **Шаг N**: <...>

### Проверки после исправления

- [ ] `dotnet build` без ошибок
- [ ] `dotnet test` без регрессий
- [ ] `npm run lint` без ошибок (если затронут frontend)
- [ ] Поведение API не изменилось (если backend)
- [ ] Документация обновлена (если затронут функционал)
```

---

## Checklist приёмки результата

После заполнения шаблона:

- [ ] Все поля заполнены, нет пустых секций
- [ ] Гипотеза сформулирована явно
- [ ] План содержит конкретные шаги
- [ ] Список проверок соответствует типу изменений (W2, W4)
- [ ] Шаблон сохранён в `wf/<task-id>/debug-brief-<N>.md`
