### 1. Методы/функции, которые могут не существовать

- `worksheet.Columns().AdjustToContents()` — существует в ClosedXML, но при пустом workbook без данных может вызвать `ArgumentException`. В нашем случае данные всегда есть (хотя бы заголовки), так что безопасно.
- `XLWorkbook()` — стандартный конструктор, стабилен с 0.95+. Версия 0.104.2 — актуальна.
- `XLColor.LightGray` — существует в ClosedXML.
- `worksheet.Range(row1, col1, row2, col2)` — существует. При `students.Count == 0` вызов будет `Range(6, 1, 5, ...)` — это **инвалидный диапазон** (конечная строка < начальной). **Это баг.**

### 2. Граничные случаи, не обработанные

| Случай | Что происходит |
|--------|---------------|
| **0 студентов в группе** | `dataRange = worksheet.Range(headerRow, 1, headerRow + 0, col-1)` = `Range(5, 1, 5, N)` — допустимо. Но `headerRow + students.Count` = 5, и range совпадает с заголовком. Стили заголовка затрутся border. Визуально не критично, но некорректно логически. |
| **0 заданий в дисциплине** | Цикл по задачам не выполнится, `col` останется = 3. Файл создастся с колонками № и Student Name, но без данных. Формально корректно, но бессмысленно. Нет предупреждения пользователю. |
| **Пустое имя дисциплины/группы** | `course.Discipline.Name` и `course.Group.Name` — не nullable по модели, но если в БД окажется пустая строка, filename будет `_Group_20260519.xlsx`. Не критично. |
| **Очень длинные имена студентов/заданий** | `AdjustToContents()` расширит колонки без ограничений. Файл откроется, но может быть неудобен. |
| **Таймаут** | Нет CancellationToken. При большом количестве студентов/оценок запрос может выполняться долго. API не имеет таймаута. |
| **Блокировка файла при скачивании** | `MemoryStream` оборачивается в `File()` — ASP.NET сам закроет. Корректно. |
| **`NotFound` для несуществующего курса** | Обработан — `return NotFound()`. |
| **Отсутствие авторизации** | Обработан — `return Forbid()`. |

### 3. Неявные допущения об окружении

| Допущение | Проблема |
|-----------|----------|
| `DateTime.Now` для даты в файле и имени файла | Используется локальное время сервера. Если сервер в UTC, а пользователь в другом часовом поясе — дата будет неверной. В остальном проекте используется `DateTime.UtcNow` (см. `UpdatedAt` в контроллере). **Несоответствие конвенции проекта.** |
| Имя файла содержит русские/кириллические символы | `Content-Disposition` с кириллицей может некорректно обрабатываться некоторыми браузерами. ASP.NET Core обычно кодирует, но без явного `ContentDispositionHeaderValue` это не гарантировано. |
| Фронтенд парсит `Content-Disposition` из заголовков | `response.headers['content-disposition']` — axios по умолчанию не exposes этот заголовок. Без `Access-Control-Expose-Headers: Content-Disposition` на бэкенде фронтенд не получит имя файла и упадет на fallback. |

### 4. Побочные эффекты за пределами задачи

| Эффект | Описание |
|--------|----------|
| **Новый пакет ClosedXML** | Добавляет ~10MB в размер сборки, транзитивные зависимости (`SixLabors.Fonts`, `ExcelNumberFormat` и т.д.). Это не «слой», но увеличивает footprint приложения. |
| **Дублирование логики запросов** | Код получения students/tasks/grades скопирован из `GetProgress`. При изменении логики одного метода второй рассинхронизируется. |
| **Чтение заголовков CORS на фронтенде** | Если `Content-Disposition` не exposed, фронтенд получит `undefined` и тихо упадет на fallback — без ошибки, но с неправильным именем файла. |

### Что нужно исправить (кратко):

1. **`Range` при 0 студентов** — добавить проверку `if (students.Count > 0)` перед применением border
2. **`DateTime.Now` → `DateTime.UtcNow`** или `DateTimeOffset.Now` — для консистентности с проектом
3. **CORS-заголовок** — либо добавить `Access-Control-Expose-Headers` в бэкенде, либо убрать парсинг имени файла на фронтенде и генерировать его там
