### Замечания к `wf/s10-amap/autonomy-map.md`

1. **S1 (Документация) — завышен уровень автономности**
   - Заявлен «полная самостоятельность», но проигнорировано ограничение AGENTS.md: документация должна отражать только реализованные изменения, а не принимать архитектурные решения. Проверка соответствия коду только верифицирует наличие ссылок на файлы, а не фактическое совпадение описания с поведением кода.
   - Стоп-сигнал «Противоречие между документацией и существующим кодом» расплывчат: нет критериев, кто и как определяет противоречие.

2. **S2 (Read-only исследование) — завышен уровень автономности**
   - Заявлен «полный (без ограничений)», но нарушает проектное правило AGENTS.md «никогда не читай файлы *.prompt», которое остаётся обязательным даже для read-only сценариев.
   - Стоп-сигнал «Попытка выполнить bash с побочными эффектами» расплывчат: не определено, что считается побочным эффектом (например, `git status` — допустимый bash без побочных эффектов).
   - Проверка «Использованы только инструменты чтения» неверифицируема постфактум без логов использования инструментов.

3. **S3 (Узкая серверная валидация) — завышен уровень автономности**
   - Средний уровень с «подтверждением перед изменением публичного API» не учитывает AGENTS.md «Не меняй публичные API без явной необходимости»: даже изменение валидации, влияющее на формат ошибок (без смены сигнатур), требует явного согласования, а не только подтверждения перед правкой API.
   - Проверка «Валидация не меняет HTTP-статусы успешных запросов» не доказывает готовность: не проверяет изменение статусов ошибок или формата ответов, которые могут сломать клиентский код.
   - Проверка «Существующие тесты не сломаны» не гарантирует отсутствие регрессий для endpoint-ов без тестов.

4. **S5 (UI-полировка) — расплывчатые стоп-сигналы и недостаточные проверки**
   - Стоп-сигнал «Нарушение валидации пользовательского ввода» расплывчат: линтинг не проверяет логику валидации, нет критериев проверки.
   - Проверка «Vuetify-компоненты используются корректно» субъективна: линтинг не проверяет корректность использования Vuetify API.
   - Проверка «Отсутствие поломок маршрутизации» не имеет автоматизированного подтверждения.

5. **S6 (Создание тестов) — недостаточные проверки**
   - Проверка «dotnet test проходит успешно» не доказывает готовность: тесты без утверждений (assertions) пройдут успешно, но не покроют заявленный сценарий. Отсутствует проверка наличия осмысленных утверждений.
   - Стоп-сигнал «Изменение тестируемого кода для «удобства тестирования»» слишком широк: не учитывает исправление багов в продакшн-коде, обнаруженных при написании тестов.

6. **S7 (Long-horizon планирование) — расплывчатые стоп-сигналы**
   - Стоп-сигнал «Попытка реализовать несколько шагов плана без остановки» расплывчат: не определено, что считается «несколькими шагами».
   - Проверка «План не противоречит ограничениям из AGENTS.md» декларативна: нет чёткого списка критериев соответствия.

7. **Сводная таблица — несоответствие детализации**
   - Столбец «Стоп-сигнал» содержит краткие формулировки (например, «изменение кода» для S1), которые не соответствуют детальным стоп-сигналам в разделах сценариев.
   - Не упомянуто проектное правило запрета на чтение `*.prompt` файлов, обязательное для всех сценариев.
